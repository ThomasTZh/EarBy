# Open source reuse and dependency plan

Reviewed against primary project documentation on 2026-10-07.
Updated 2026-10-09: source uses Preferences DataStore, manual composition and SQLite.
The recorded KSP/AGP compatibility probe rejected Room/Hilt on the selected toolchain;
see STATUS. The plan review did not re-query package releases or update dependencies.
These are selected components and introduction rules. This review installs nothing.

## Policy

Use existing packages for infrastructure. Write only application-specific musical
constraints, recipes, state transitions and narrow integration adapters.
The JVM standard library also counts as reuse; a separate package is not needed for
MIDI arithmetic or a small constrained shuffle policy.

Preserve existing catalog pins. The proposed versions below were published when
reviewed; compatibility with this project's complete graph must be established by
the owning work package. Pin all other packages to an immutable release/commit during
that package's dependency step, before implementing against their APIs. Record why a
selected package cannot be used before substituting it. Never leave production build
inputs on a moving branch.

## Native integration choice

The only pinned native source is miniaudio (WAV decode/conversion and the test oscillator),
staged by `scripts/fetch-native-sources.sh` from `tools/native/sources.json` and linked by
`core/audio/src/main/cpp/CMakeLists.txt`. The instrument renderer is original project code
(`sample_player.cpp`), so there is no third-party synthesizer build to pin or configure; the
FluidSynth, GCEM and Signalsmith sources of the earlier engine were removed in V4.

Use shared libraries and retain source revision/build recipe/license materials for
every included native component. Audit the final native dependency list, including
libc++ if shared, and check ELF and APK alignment.

Sources: [miniaudio](https://github.com/mackron/miniaudio),
[Android page-size guidance](https://developer.android.com/guide/practices/page-sizes).

## Deliberate exclusions

- ExoPlayer is unnecessary for generated PCM while SimpleBasePlayer provides media
  integration. Reconsider only for a real encoded-media consumer.
- Do not add SoundPool or a second voice player: independent clocks would weaken the
  timeline contract.
- music21 stays in development tooling; Android must not embed Python. Small domain
  arithmetic and product sequencing remain pure Kotlin behind tested contracts.
- Do not introduce a custom database, serializer, FFT, WAV codec, resampler, DI framework,
  notification framework or speech synthesizer when the selected package covers it.
- Do not replace the operating system's build/SDK tools with an unrelated framework.

## Artifact records to create during implementation

Create THIRD_PARTY_NOTICES.md and a machine-readable native/assets source manifest in
WP2.1/2.2. Each record needs name, role, runtime/development classification, upstream
URL, immutable version/revision, archive/file SHA-256, license file, modifications,
build flags and owning package. Python locks and Gradle checksums supplement it.

Asset provenance additionally records model revision or recording source, phrase text,
generation parameters, postprocessing command, final format/hash and human review.
A model seed does not guarantee byte-identical regeneration on different accelerators;
the approved WAV checksum identifies the shipped voice.

Preserve existing pins in every unrelated task. Newer release pages sometimes show
alpha dependencies in their examples; select the stable release intentionally.

## 2026-10-11 review consumer changes

No dependency or toolchain version changed. core:audio now consumes the existing pinned
kotlinx.serialization JSON parser (Apache-2.0) for voice manifests instead of regular expressions.
Review instrumentation consumes the existing pinned DataStore library for actual corruption/
future-schema tests. No runtime network component or permission was added. Native source locks,
asset hashes/licenses, Python locks and Gradle verification metadata remain unchanged.
The review variant reuses debug dependencies/assets and has its own app/test IDs.
