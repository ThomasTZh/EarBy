## Help page — 0.9.33

The in-app Help page is split into short sections: how to use the app, the three learning modes, one
card per mode, the root/tonic range rules, and presets/sound. The page now explains the current
root-only range behavior, perfect-pitch exceptions, always-open Advanced controls, fresh preset

## Responsive sound sliders — 0.9.32

The Settings page keeps each slider position in Compose state, so the thumb and percentage follow
the finger without waiting for the settings repository. During a drag, writes are coalesced with an
80 ms debounce; releasing the slider flushes the final value immediately. External settings changes
still update the thumb when that slider is not being dragged. A focused ViewModel test covers the
debounce and release flush; `check-fast.sh` passes. Full QA remains deferred.

## Root/tonic ranges — 0.9.31

The setup range now restricts only root notes or key tonics:

- non-root notes may leave the root range but must stay inside MIDI 21-108;
- perfect pitch keeps "Lowest note / Highest note" and excludes unavailable classes with a warning;
- every other setup screen uses "Lowest root note / Highest root note";
- roots and keys that cannot fit are skipped, and a fixed root that no longer fits is cleared;
- the Advanced switch is removed; the header remains and its controls are always open;
- existing preset numbers are reinterpreted as root bounds, with no silent migration.

`scripts/check-fast.sh` passes, including all host suites and lint. The debug APK passed
`check-apk.sh` and is installed as versionCode 40. Full QA was not run, per the owner's instruction.

## Random preset runs — 0.9.30

Presets no longer carry a run seed:

- applying any preset writes `seed = null` into the active mode setup, even when the stored preset
  has an old seed;
- saving into a slot writes `seed = null` at the preset level, even when the current setup has the
  last run's seed;
- the next Start draws a fresh seed, so applying the same preset twice gives different sequences;
- legacy preset rows may still contain a stored seed, but it is ignored and overwritten with null
  on the next save. No schema migration was required.

Focused `ViewModelTest` coverage now asserts both the apply and save paths. Full QA was not run for
this change, per the owner's instruction.

## Uniform output trim — 0.9.28

A single **1.13x** final-mix trim adds about **+1.06 dB** to the music, voice and separator. It is
applied once to the completed PCM after all mixing, so the balance is unchanged and there is no
compression, limiting or per-note gain.

- The loudest current note is 0.835, so the trimmed peak is about **0.943**, below the 0.95 target.
- The 0-100% sliders keep their 50% reviewed normal; the trim sits after the gain controls.
- The default music gain and the 0.120 RMS samples are unchanged.
- The 100% slider position can still clip on loud chords; that remains user headroom.

## Volume sliders — 0.9.27

Both the music and voice sliders span **0-100%** and sit at **50% by default**. The 50% point is
the reviewed near-perfect volume; 100% is twice that level. The sliders use one readable
percentage scale even though their stored gains differ.

- the stored music gain remains 1.0 and the synth samples remain at 0.120 RMS;
- music 100% maps to gain 2.0; voice 100% maps to gain 0.5;
- no settings or preset migration is needed because stored defaults stay 1.0 / 0.25;
- the settings and Play screenshots show 50% for both and still need a new visual baseline approval.
  The old baselines were not overwritten.

The previous 0.9.26 4x scale and 25% label are superseded.

## Play note readout — 0.9.24

The Play tab's `Current setup` card now shows a `Notes:` line while a session is `PLAYING`:

- a single-note item shows one name, for example `Notes: C4`;
- a chord shows all of its notes, for example `Notes: C4, E4, G4`;
- notes are deduplicated and keep generation order;
- the line is absent while idle, connecting or preparing.

The value is `SessionSnapshot.currentNotes`, read through the app-private session-state query.
It is not added to media metadata or the notification/lockscreen.

This is a deliberate owner-requested debug exception to the hidden-answer rule (decision D44): the
line exposes the generated pitches before the spoken answer. The answer text, media metadata and
lockscreen remain unchanged. Do not add the notes to those surfaces.
